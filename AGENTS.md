# herdr-gitdiff

A Herdr mod: a Changes panel (changed files, each opening into its diff). Layout and
how the pieces fit: `docs/ARCHITECTURE.md`. User docs: `README.md`.

- `mod/` (the Changes panel) and `menu/` (its `<leader>g` menu) are what gets installed
  (`./install.sh`); keep each to `*.js`, `mod.json` and
  `icons/` (`*.svg` plus `LICENSE-lucide.txt`, which ships with them).
- One name everywhere: the repo, the installed mod (`mods/herdr-gitdiff`, `DEST`
  in `install.sh`), the `"title"` in `mod.json` (the install's guard reads it), the
  `content.mod` in a layout, the `herdr-gitdiff.<command>` bindings in `keys.json`,
  and the assets, which are addressed from the app home: an icon is
  `svg("mods/herdr-gitdiff/icons/x.svg")`.
- `mod/` is flat, except `mod/ui/` and `mod/utils/` (`install.sh` copies `mod/*.js`, `mod/ui/*.js` and `mod/utils/*.js`, nothing else): the layer is
  in the name. `mod/ui/ui-*.js` draw from values and callbacks the view passes in (never `this`); everything else
  is pure or takes `exec` & co. `mod/utils/` is for what does not know this mod (it takes Herdr's functions as arguments, imports only from `utils/`), so it can become an SDK. Only `ui/` and `utils/` are folders: don't add others.
- `parse.js`, `ansi.js`, `lexer.js` stay pure (no `herdr` imports). `git.js` and
  `highlight.js` take `exec` & co. as arguments. Keep it that way so `npm test` covers them.
- Tests: `npm test` (node:test, one file per module).
- Traps already found: never nest a second scroll area in the list; don't use
  `overflow_scrollbar()` (panel stuck on "could not be re-rendered").
- `// shortcut:` comments mark known simplifications; keep them honest.
- Styling (gpui builders, there is no CSS): in `ui-*.js` name each style as a small function
  `const card = (theme) => (el) => el.px(14).py(8)…` and call it as `card(theme)(v_flex())`, so
  the builders read as structure (children, `when`) and a style has one place to change. A chain of
  more than ~4 style calls inside a `.child(...)` is a sign it needs a name. Logic that is not
  drawing (splitting a message, a clamp) goes to a pure module with a test.
- Comments: JSDoc (`@typedef`, `@param`, `@returns`) on exported functions that take an options
  object, return an object, or take callbacks, so each field has a type and a description. Plain
  `//` for the why (a trap, a constraint, a choice), and nothing on trivial one-liners.
- `jsconfig.json` and `*.d.ts` in `mod/` are generated by the app and git-ignored.
